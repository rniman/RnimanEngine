# M02 계획 — ImGui로 조작하는 정적 3D 모델 데모

[로드맵](../roadmap.md) · [엔진 설계](../design.md) · [완료된 마일스톤](../milestones/README.md)

## 상태와 목표

- 상태: 계획 수립, 구현 전. 계획 기준일은 2026-10-21이다.
- Git 태그: 미태깅. 대상 커밋·달성일·버전 번호는 완료 시 정한다.
- 이 문서는 진행할 범위와 완료 기준을 관리하는 계획이다. 완료 후 실제 달성 범위·검증 결과·제약을 `docs/milestones/`에 별도 기록하고 이 계획에서 연결한다.
- 현재 기준: 고정 큐브·단일 PNG·카메라·기본 Phong 데모가 동작하고 공통 소스는 Engine, 실행·조작 코드는 Sandbox에 배치되어 있다. ImGui·모델 익스포터/로더·ECS는 아직 구현하지 않았다.
- 목표: **ImGui 최소 도입 → Unity 정적 메시·Transform 익스포트 → bin 로딩 → GPU 업로드 → Phong 렌더링**을 Sandbox의 실제 사용 흐름으로 연결한다.

ImGui를 먼저 붙여 기존 장면의 편집 경로를 확보한 뒤 외부 모델로 확장한다. 모델·렌더 데이터 경계가 실제로 사용되는 장면을 확보하고, 그다음 마일스톤에서 일반 오브젝트 방식과 ECS를 비교한다.

## 1단계 · ImGui 최소 도입

| 대상 | 구현 범위 |
|---|---|
| 연결 | Win32·DirectX 12 백엔드 초기화·프레임 갱신·UI 그리기·종료를 기존 창/렌더러 수명에 맞춰 연결 |
| 편집 | 기존 큐브 선택, Transform 편집, 카메라 위치·조명 방향/강도 조절 |
| 갱신 | 자동 회전 정지/재개 제공. 편집한 값이 다음 자동 갱신에 즉시 덮어써지지 않도록 편집과 데모 갱신의 관계 정의 |
| 상태 | 개체 수·프레임 시간 등의 최소 상태 표시. 프레임 표시를 CPU/GPU 분리 성능 측정으로 해석하지 않음 |
| 입력 | UI의 마우스·키보드 사용 여부에 따라 앱 조작을 구분하고 기존 포커스·입력 소비 계약 유지 |
| 자원 | UI용 디스크립터·업로드 자원을 GPU 완료 전에 재사용/파괴하지 않으며 리사이즈·종료 순서에 통합 |

플랫폼 입력은 ImGui에 전달하고, 앱의 카메라·조명 조작에 사용할지는 UI 입력 캡처 상태로 구분한다. 관련 근거는 [공식 백엔드 문서](https://github.com/ocornut/imgui/blob/master/docs/BACKENDS.md)와 [입력 전달 FAQ](https://github.com/ocornut/imgui/blob/master/docs/FAQ.md#q-how-can-i-tell-whether-to-dispatch-mousekeyboard-to-dear-imgui-or-my-application)를 따른다. 구체적인 버전·도입 경로·라이선스·빌드 연결은 실제 도입 시 기록한다.

패널은 Sandbox의 편집 흐름에 두고 일반 장면 데이터가 ImGui 타입을 요구하지 않도록 한다. Win32·D3D12 어댑터의 구체적인 인터페이스는 현재 창·렌더러에 연결하는 데 필요한 범위에서 정한다.

## 2단계 · 정적 모델 로딩과 렌더링

첫 지원 범위는 단일 정적 메시, 위치·법선·UV0·삼각형 인덱스, 오브젝트 Transform과 단일 BaseColor PNG를 사용하는 기본 Phong 재질이다. 한 메시를 여러 Transform으로 배치할 수 있게 한다. 첫 전달에서는 현재의 유한한 아핀 Transform·양수 행렬식 제약을 유지하고 반전 Transform은 지원 범위에 포함하지 않는다.

1. **익스포터와 규격**: Unity에서 위 데이터를 자체 bin 형식으로 내보낸다. 파일 식별값·버전·바이트 순서·필드 타입·개수·참조 표현과 재익스포트 조건을 작은 규격으로 먼저 명시한다. 세부 바이트 배치는 구현 전에 확정한다.
2. **에셋 계약**: 정면·거리 단위·Transform 적용 위치, 좌표 변환·삼각형 winding·노멀·UV·BaseColor 경로/색 공간을 정한다. 현재 CPU/HLSL의 행 벡터·행 우선 전달 계약에 맞춘다.
3. **CPU 로딩**: 파일 범위·크기 계산·인덱스 범위·필드 값·참조를 검사하고 CPU 메시 데이터로 반환한다. 오류에는 파일과 원인을 남긴다.
4. **GPU 생성**: 정점·인덱스 버퍼 생성과 업로드를 렌더링 코드가 담당한다. 초기 업로드·그리기·파괴 사이의 소유권과 GPU 완료 조건을 명시한다.
5. **장면 연결**: 로딩한 메시와 Transform을 렌더 데이터로 전달해 기존 Phong으로 그린다. ImGui 편집 패널도 같은 모델 상태 변경 경로를 사용한다.

파서와 GPU 업로드의 경계를 유지한다. 모델 데이터·그리기 참조를 도입하며 렌더러의 고정 큐브 가정을 필요한 범위에서 해소한다. 기존 큐브는 비교·회귀용 기준으로 유지하고 새로운 범용 자원 관리자나 전체 씬 형식을 선행 구현하지 않는다.

재현 가능한 작은 기준 모델을 익스포터·로더와 함께 준비하고, 저장소에서 추적할 기준 파일과 별도 준비할 원본의 위치·출처·준비 방법을 명시한다. 기존 루트 Assets의 Git 제외 정책을 모든 새 기준 에셋에 자동 적용하지 않는다.

## 완료 기준

| 결과 | 확인 기준 |
|---|---|
| 편집 가능한 데모 | 기존 큐브와 로딩한 모델에 Transform·카메라·조명 편집 경로가 연결되고 자동 회전과 편집 상태가 일관됨 |
| 데이터 전달 재현 | 문서의 준비·익스포트·로딩 절차로 기준 모델을 그릴 수 있고 bin 규격 버전과 재익스포트 조건이 명시됨 |
| 로더 계약 | 기준 데이터의 필드·개수·인덱스를 대조하고 누락·잘림·미지원 버전·잘못된 인덱스 등의 실패를 검사 |
| 렌더링 계약 | 정점·인덱스·Transform·노멀·UV가 기대대로 전달되며 기본 Phong과 여러 Transform 배치 결과를 기준 데이터·GPU readback으로 확인 |
| 통합과 수명 | x64 Debug·Release 빌드·실행, 영향받는 Smoke와 추가 계약 검증 통과. UI·모델 자원의 생성·리사이즈·종료에서 진단 오류를 남기지 않음 |
| 문서와 상태 | 현재 구현·지원 데이터·준비 방법·검증 결과를 README·설계·의존성·마일스톤에 반영하고, 완료된 범위만 달성으로 기록 |

위 표는 앞으로 구현할 결과의 완료 기준이다. 현재 빌드·실행 결과를 M02 기능의 검증으로 취급하지 않는다.

## 진행 순서와 후속 범위

1. 현재 Phong 데모에 ImGui의 수명·입력·최소 패널을 연결한다.
2. 기준 모델과 bin 규격을 정하고 Unity 익스포터·CPU 로더·실패 검증을 맞춘다.
3. 메시 GPU 업로드·그리기를 연결하고 모델을 편집 가능한 데모로 통합한다.
4. 완료 기준을 확인하고 결과·제약·태그를 기록한다.

이후 일반 오브젝트 기준 구현과 ECS로 같은 모델 장면을 관리한다. 생성·삭제·이동/회전·갱신 대상 선택을 비교하고, 동일한 작업량·빌드 구성에서 갱신과 렌더 데이터 수집 비용·사용성을 기록한다. ECS 저장 방식은 해당 단계에서 정한다.

재질 다중화·씬 계층·스켈레톤/애니메이션·PBR과 도킹/다중 뷰포트·독립 에디터는 후속 확장으로 둔다. Engine 라이브러리 프로젝트는 독립 빌드·재사용 필요에 따라 분리하며 이 마일스톤의 필수 완료 조건으로 두지 않는다.
