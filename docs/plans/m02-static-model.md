## 2단계 · 정적 모델 로딩과 렌더링

첫 지원 범위는 단일 정적 메시의 위치·법선·UV0·삼각형 인덱스, Transform, 단일 BaseColor PNG의 기본 Phong 재질이다. 한 메시를 여러 Transform으로 배치하며 현재의 유한한 아핀·양수 행렬식 제약을 유지한다. 반전 Transform은 제외한다.

1. **익스포터·규격**: Unity → 자체 bin. 구현 전 식별값·버전·바이트 순서·필드 타입·개수·참조 표현·바이트 배치·재익스포트 조건을 정한다.
2. **에셋 계약**: 정면·거리 단위·Transform 적용 위치·좌표 변환·winding·노멀·UV·BaseColor 경로/색 공간을 현재 CPU/HLSL 규약에 맞춘다.
3. **CPU 로더**: 파일 범위·크기 계산·인덱스·필드 값·참조를 검사하고 CPU 메시를 반환한다. 오류에 파일·원인을 남긴다.
4. **GPU 생성**: 렌더링 코드가 정점·인덱스 버퍼 업로드·그리기·파괴와 GPU 완료 조건을 관리한다.
5. **장면 연결**: 메시·Transform을 렌더 데이터로 전달해 Phong으로 그리고 ImGui도 같은 상태 변경 경로를 사용한다.

파싱과 GPU 업로드를 분리하고 고정 큐브 가정은 필요한 범위에서 해소한다. 큐브는 회귀 기준으로 유지하며 범용 자원 관리자·전체 씬 형식은 선행 구현하지 않는다.

작은 기준 모델을 익스포터·로더와 함께 준비하고 추적 파일·별도 준비 원본의 위치·출처·준비 방법을 명시한다. 루트 Assets의 Git 제외 정책을 새 기준 에셋에 자동 적용하지 않는다.

## 완료 기준

| 결과 | 확인 기준 |
|---|---|
| 편집 데모 | 큐브·모델의 Transform·카메라·조명 편집과 자동 회전 상태가 일관됨 |
| 데이터 전달 | 문서의 준비·익스포트·로딩 절차로 기준 모델 재현. 규격 버전·재익스포트 조건 명시 |
| 로더 | 기준 필드·개수·인덱스 대조, 누락·잘림·미지원 버전·잘못된 인덱스 실패 검사 |
| 렌더링 | 정점·인덱스·Transform·노멀·UV·Phong·여러 Transform 배치를 기준 데이터·GPU readback으로 확인 |
| 통합·수명 | x64 Debug·Release 빌드·실행, 영향받는 Smoke·추가 계약 검증 통과. UI·모델 생성·리사이즈·종료의 진단 오류 없음 |
| 문서 | 지원 데이터·준비 방법·검증 결과를 README·설계·의존성에 반영하고 실제 달성·제약·대상 커밋·태그를 마일스톤에 기록 |

현재 데모의 검증은 위 미구현 기능의 통과를 뜻하지 않는다. 완료 시 이 계획에서 달성 기록을 연결한다.

## 후속 범위

일반 오브젝트·ECS 비교에서 생성·삭제·이동/회전·갱신 대상 선택을 같은 작업량·빌드 구성으로 확인한다. 저장 방식은 해당 단계에서 정한다.

재질 다중화·씬 계층·스켈레톤/애니메이션·PBR, 도킹/다중 뷰포트·독립 에디터는 후속이다. Engine 라이브러리 분리는 이 마일스톤의 완료 조건이 아니다.
