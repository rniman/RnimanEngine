## M03 동적 오브젝트 관리

로딩된 Cube·Sphere·Helmet을 공유하는 인스턴스의 생성·삭제·선택·개별 편집을 구현했다. 사용 방법은 [README](../README.md#개발-ui), 데이터·수명은 [오브젝트 저장과 렌더 입력](design.md#오브젝트-저장과-렌더-입력)을 따른다.

저장·불러오기, 복제·Undo, 화면 클릭 선택, 계층, 실행 중 모델 자원 추가·삭제는 후속 범위다. 변경 추적을 통한 상수 재계산 생략은 갱신 비용과 관리 복잡도를 비교해 결정한다. ECS 비교에서 실제 재사용할 책임이 드러날 때 App 내부 로직의 분리를 검토한다.

## ECS 비교와 후속 선택

일반 오브젝트와 같은 동작을 ECS로 구현하고 UI·렌더러를 공유한다. 동일 초기 상태·입력·경과 시간에서 변환과 렌더링 결과를 확인한 뒤, 같은 개체 수·작업량·Release 구성에서 갱신과 렌더 데이터 수집 비용을 구분해 반복 측정한다. 저장 방식·핸들 재사용·참조 무효화·순회 중 구조 변경 정책은 구현 단계에서 정한다. 측정 전 성능 우위를 가정하지 않는다.

계층 모델은 실제 다중 노드 에셋을 도입할 때 부모 관계·로컬 변환·메시 참조를 보존하고 World 행렬을 계산해 노드별로 그리는 방향으로 검토한다. 합성 World를 단일 TRS로 다시 분해하는 현재 제한을 이때 해소한다. 다중 재질·재질별 UV·텍스처 식별은 실제 에셋 요구에 맞춰 확장한다.

스켈레톤·애니메이션, 그림자·IBL·후처리, 다른 그래픽스 API, 물리·AI·오디오·멀티스레딩·독립 에디터는 사용하는 데모가 생길 때 추가한다. Engine 라이브러리 분리는 독립 빌드·재사용 수요가 생길 때 결정한다.
