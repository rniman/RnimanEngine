개발 방향과 단계별 완료 기준을 관리한다. 상세 계획은 `docs/plans/`, 완료된 마일스톤의 달성·검증 기록은 `docs/milestones/`에 둔다. 현재 구현 요약은 [README](../README.md#현재-상태), 완료 기록은 [마일스톤 목록](milestones/README.md)을 따른다.

## 목표와 범위

| 영역 | 개발 방향 |
|---|---|
| 미니 게임 엔진 | 개발 중간부터 상호작용 데모와 작은 프로젝트로 실제 사용성을 확인한다. |
| D3D12 | 주력 API로 초기화부터 리소스 관리, 명령 제출, 동기화와 화면 출력까지 구현한다. |
| ECS | 여러 엔티티와 시스템이 함께 동작하는 게임 로직에 사용하고, 일반 오브젝트 방식과 비교한다. |
| 렌더링 | 기본 Phong 조명에서 PBR까지 확장하고, 재질과 조명을 장면에서 조절한다. |
| 실시간 도구 | 먼저 ImGui로 Transform·카메라·조명 편집과 프레임 상태 표시를 연결하고, 재질 편집·추가 진단은 해당 기능을 구현할 때 확장한다. |
| 리소스 | Unity에서 정적 메시·Transform을 bin 파일로 익스포트해 엔진에서 읽는 흐름부터 만들고, 재질·씬 계층·애니메이션으로 확장한다. |

D3D11·OpenGL은 비교용 확장 후보다. 초기에는 D3D12에 집중하고, 다른 구현이 필요해질 때 공통 경계를 검증한다. 모든 API의 기능 동등성이나 실행 중 교체는 초기 범위에 포함하지 않는다.

추가 렌더링, 물리, AI, 오디오, 멀티스레딩, 독립 에디터 등은 사용할 샘플과 확인할 문제가 생겼을 때 범위를 정한다.

## 개발 순서

2026-10-21 개발 순서를 **ImGui 최소 도입 → 3D 모델 로딩·렌더링 → 일반 오브젝트와 ECS 비교**로 정리했다. ImGui와 정적 모델 데모를 다음 마일스톤으로 묶어 단계별로 연결한다.

| 단계 | 만들 것 | 상태·완료 기준 |
|---|---|---|
| 1 | 창과 D3D12 삼각형 | 완료. 초기화·명령 제출·화면 출력·종료 흐름을 연결 |
| 2 | 직접 정의한 메시, 텍스처, 카메라, 기본 Phong 조명 | 첫 마일스톤 완료. 여러 큐브를 그리고 카메라와 조명을 조절 |
| 3 | ImGui 최소 도입 | 계획. 기존 큐브에서 Transform·카메라·조명 편집, 자동 회전 정지/재개, 프레임 상태 표시와 UI/앱 입력 분리 |
| 4 | 정적 3D 모델 로딩·렌더링 | 계획. Unity 익스포터 → bin → CPU 메시 → GPU 업로드 → 기존 Phong 렌더링을 연결하고 ImGui로 모델 Transform·조명을 조절 |
| 5 | 일반 오브젝트 방식과 ECS 비교 | 모델 장면 확보 후 진행. 같은 장면·렌더러·개체 수·작업으로 동작·사용성과 갱신/렌더 데이터 수집 비용을 비교 |
| 6 | 재질·씬 계층 확장과 PBR | 후속. ECS 장면에서 PBR 재질과 조명을 조절하며 데이터 전달 범위를 확장 |

**첫 마일스톤 달성 (2026-10-13 재검증):** 2단계까지의 데모를 문서대로 빌드·실행하는 기준을 충족했다. 기능 제약은 [첫 마일스톤 기록](milestones/v0.1.0-sandbox.md)에 남긴다. 각 단계에서 실행 가능한 결과를 유지하고 스켈레톤·애니메이션은 사용하는 데모에 맞춰 추가한다.

## 다음 마일스톤

[M02 · ImGui로 조작하는 정적 3D 모델 데모](plans/m02-static-model.md)를 계획한다. 태그와 달성일은 아직 정하지 않았다.

- 먼저 기존 큐브에 ImGui 편집·상태 표시를 연결한다.
- 이어서 단일 정적 메시·Transform을 Unity에서 내보내 자체 bin 로더와 기존 Phong 렌더러에 전달한다. 첫 재질은 단일 BaseColor PNG를 사용하는 기본 Phong으로 제한한다.
- 한 메시를 여러 Transform으로 배치하고 같은 편집 경로를 사용한다. ECS 비교의 기준 장면은 이 결과 위에서 구성한다.

버전이 있는 파일 규격, 좌표·단위·winding·노멀·UV 계약과 로딩 실패 처리는 모델 전달 단계에서 함께 확정한다. 세부 범위·진행 순서·완료 기준은 M02 문서에서 관리한다. Engine 라이브러리 프로젝트는 실제 독립 빌드·재사용 필요에 따라 분리하며 M02의 선행 조건으로 두지 않는다.
