## 목표와 범위

D3D12 기반 미니 게임 엔진을 작은 상호작용 데모에 사용하며 개발한다. ECS는 일반 오브젝트 방식과 비교하고, 렌더링은 Phong에서 PBR로, 리소스는 Unity 정적 메시·Transform에서 재질·씬 계층·애니메이션으로 확장한다. 개발용 편집·진단 UI는 ImGui로 시작한다.

D3D11·OpenGL은 비교용 후보다. 다른 API의 기능 동등성·실행 중 교체, 물리·AI·오디오·멀티스레딩·독립 에디터는 실제 사용할 샘플과 문제가 생길 때 범위를 정한다.

## 개발 순서

| 단계 | 결과 | 상태·기준 |
|---|---|---|
| 1 | 창과 D3D12 삼각형 | 완료. 초기화·제출·화면 출력·종료 연결 |
| 2 | 메시·텍스처·카메라·Phong | 첫 마일스톤 완료. 큐브 3개와 카메라·방향광 조작. [2026-10-13 재검증](milestones/v0.1.0-sandbox.md) |
| 3 | ImGui 최소 도입 | 구현. 기존 큐브 편집·회전 정지/재개·상태 표시·UI/앱 입력 분리 |
| 4 | 정적 모델 로딩·렌더링 | 계획. Unity → bin → CPU 메시 → GPU 업로드 → Phong·ImGui 편집 |
| 5 | 일반 오브젝트·ECS 비교 | 모델 장면 확보 후 진행. 같은 장면·개체 수·작업·렌더러에서 동작·사용성·갱신/수집 비용 비교 |
| 6 | 재질·씬 계층·PBR | 후속. ECS 장면에서 재질·조명을 편집하고 데이터 전달 범위 확장 |

단계마다 실행 가능한 결과를 유지한다. 스켈레톤·애니메이션은 사용하는 데모에 맞춰 추가한다.

## 다음 마일스톤

[M02 · ImGui로 조작하는 정적 3D 모델 데모](plans/m02-static-model.md)는 3·4단계를 묶는다. ImGui 단계는 구현했으며 정적 모델 단계는 미구현이다. M02 전체 태그·달성일은 미정이다. 단일 정적 메시·Transform·BaseColor PNG의 기본 Phong 재질부터 연결하고, 한 메시를 여러 Transform으로 배치해 ECS 비교의 기준을 만든다.

파일 버전·좌표/단위·변환 규칙·실패 처리와 완료 기준은 M02 문서에서 관리한다. Engine 라이브러리 분리는 독립 빌드·재사용 필요에 따라 결정하며 선행 조건으로 두지 않는다.
