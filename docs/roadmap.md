# 개발 목표와 순서

## M02 상태와 완료 기준

단일 메시·Submesh·재질의 로딩·GPU 업로드·Phong·ImGui 편집과 자동 검증은 연결되어 있다. 전체 달성일·태그는 확정하지 않았다.

- Transform을 Quaternion 저장으로 전환하고 로딩의 Euler 복원 경로를 제거했다. 양쪽 ±90도·인접 각도 회귀 검사를 추가했으며 전단·특이·반전 거부는 유지한다. [계층 지원 범위와 수정 이력](static-model.md#계층-지원-범위와-알려진-문제)을 따른다.
- 기준 BIN·이미지를 준비하고 지원 버전·변환·재익스포트 조건을 재현할 수 있어야 한다. [에셋 준비](static-model.md#기준-에셋-준비)를 따른다.
- 로더의 정상·손상 입력, GPU 메시·UV·색 공간·Wrap·다중 인스턴스, 생성·리사이즈·종료를 Debug·Release에서 확인한다.
- 최신 v2 세 모델의 실제 화면·Transform/카메라/조명 편집을 확인하고 수행 범위·제약·대상 커밋을 기록한 뒤 마일스톤을 확정한다. 기존 자동·수동 결과는 [검증 기록](development.md#검증-기록)과 구분한다.

## 다음 구현안: 일반 오브젝트 장면

현재 `SandboxApp::mObjects`는 고정 배열이며 모델 번호 `{0,1,2}`와 대응한다. 다음 단계에서는 미리 로딩한 모델 자원을 공유하면서 CPU 인스턴스만 생성·삭제한다. 아래는 구현 전 제안이며 현재 코드의 확정된 규칙이 아니다.

| 대상 | 최소 구현안 |
|---|---|
| 데이터·저장 | 고유 ID·모델 번호·Transform·자동 회전 상태를 값으로 보관하는 동적 목록. 우선 `std::vector` 검토 |
| 식별·선택 | 배열 인덱스와 ID를 분리하고 실행 중 ID를 재사용하지 않는 방식부터 검토. 요소 포인터·참조를 장기 보관하지 않음 |
| 조작 | 모델 선택 후 생성, 선택 오브젝트 삭제, 기존 Transform·자동 회전 편집 연결 |
| 갱신·그리기 | 목록을 갱신한 뒤 변환 상수·모델 번호를 수집해 기존 Renderer에 전달 |
| 구조 변경 시점 | 목록 순회 밖에서 생성·삭제 적용. UI 요청 → 구조 변경 → 갱신 → 렌더 데이터 수집 순서를 후보로 검토하고 편집·자동 회전 우선순위를 검증 |
| 코드 소속 | Sandbox의 작은 장면 클래스로 목록 관리·갱신·수집을 분리하는 안. ImGui·오류 UI는 앱에 유지하고 재사용 수요가 생기면 Engine 이동 검토 |

완료 기준은 같은 모델의 독립 인스턴스 편집, 중간 요소 삭제 후 선택·상태 유지, 전체 삭제 후 빈 장면 렌더링·재생성, 반복 생성·삭제·리사이즈·종료다. 인스턴스 생성·삭제 시 메시·텍스처 재업로드가 없어야 한다. 실행 중 GPU 모델 추가·삭제, 계층, 범용 자원 관리자·컴포넌트 체계는 이 단계에 포함하지 않는다.

모델·이미지 준비 함수 추출은 초기화 복잡도나 재사용 수요가 생기면 수행한다. 데모별 폴더·확장자 선택은 Sandbox, CPU 파싱·디코딩은 Assets, GPU 생성은 Renderer의 책임으로 유지한다.

## ECS 비교와 후속 선택

일반 오브젝트와 같은 동작을 ECS로 구현하고 UI·렌더러를 공유한다. 동일 초기 상태·입력·경과 시간에서 변환과 렌더링 결과를 확인한 뒤, 같은 개체 수·작업량·Release 구성에서 갱신과 렌더 데이터 수집 비용을 구분해 반복 측정한다. 저장 방식·핸들 재사용·참조 무효화·순회 중 구조 변경 정책은 구현 단계에서 정한다. 측정 전 성능 우위를 가정하지 않는다.

계층 모델은 실제 다중 노드 에셋을 도입할 때 부모 관계·로컬 변환·메시 참조를 보존하고 World 행렬을 계산해 노드별로 그리는 방향으로 검토한다. 합성 World를 단일 TRS로 다시 분해하는 현재 제한을 이때 해소한다. 다중 재질·재질별 UV·텍스처 식별은 실제 에셋 요구에 맞춰 확장한다.

스켈레톤·애니메이션, 그림자·IBL·후처리, 다른 그래픽스 API, 물리·AI·오디오·멀티스레딩·독립 에디터는 사용하는 데모가 생길 때 추가한다. Engine 라이브러리 분리는 독립 빌드·재사용 수요가 생길 때 결정한다.

## 기존 계획과 문서 통합

기존 `docs/plans/m02-static-model.md`의 단일 정적 메시·Transform·BaseColor·Phong·ImGui 목표와 완료 기준은 이 문서와 [정적 모델 계약](static-model.md)으로 통합했다. `docs/milestones/README.md`의 목록은 위 단계 표가 대신하며 [v0.1.0 달성 기록](milestones/v0.1.0-sandbox.md)은 유지한다. 삭제한 두 문서를 현재 기능의 근거로 링크하지 않는다.

초기 M02에 비해 세 모델 동시 로딩·JPEG·Wrap U/V·고정 손상 검사 fixture가 추가됐다. 씬 계층·다중 재질·PBR은 처음부터 후속 범위다. 초기 계획의 유한한 아핀·양수 행렬식 표현보다 현재 로더는 양수 Scale TRS로 좁혀져 있으며, 렌더러의 행렬 허용 범위와 구분한다. v1·실험 포맷은 v2 재익스포트 대상으로 대체했지만 기본 큐브·PNG 전용 API·Legacy BIN 거부 검사는 유지한다.
